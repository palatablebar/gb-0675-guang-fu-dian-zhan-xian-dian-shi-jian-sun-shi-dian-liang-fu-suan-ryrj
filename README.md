# 光伏电站限电事件与损失电量复算

给新能源场站运营分析员使用。仅用有效对照逆变器和相同辐照区间拟合基线；重叠限电事件先求并集再积分。

七个业务模块：遥测采信、设备映射、事件切片、基线拟合、损失核算、能量对账、运行归档。

```sh
docker compose up --build -d
docker compose exec -T app pytest -q
```

访问 http://localhost:18244 。启动直接载入现场脏批。切换双站完整批和双站旧编码批可对照核验。区域同日多站报送按以下裁定形成正式结果：

- **同名编号**：正式身份=场站+原编号。北岭 INV-A 与南岭 INV-A 各自独立，两站同名 E-01 形成各自并集；去重、冲突、并集、对照、积分全部按复合键，不按原编号跨站合并。
- **缺少场站依据**：场站列为空或未登记的记录一律隔离待查，保留原值与原始行号，不落入任何场站结果，不填 0，不丢弃。
- **对平**：场站内事件并集=切片、基线=实际+损失各自对平；区域合计=各站结果之和，并以全批直接合计复核，未归集到登记场站的行会让两口径相抵，批次转待复核。
- **批次**：补正或重算失败保留旧版；同一依据重试生成相同批号，不新增批次；行守恒保证不丢失记录。

页面显示场站归属、各站可结算损失与待查片段。双站完整批：北岭 INV-A 重叠事件取并集后30分钟、基线100kW、实际60kW、损失20kWh，INV-B 损失6.6667kWh；南岭同名 INV-A 与 E-01 独立核算，基线100kW、实际80kW、30分钟、损失10kWh。区域合计36.6667kWh，等于两站之和。无合格对照或遥测冲突必须保持未定，不能填0。

各模块页面对应 `/<模块英文名>`，各模块执行入口为 `POST /api/<模块英文名>`，不传参即可独立演示。完整运行 `POST /api/runs` 支持 `dataset`（dirty/clean/legacy）、`csv_text` 与 `overrides` 参数。批次历史 `GET /api/runs`，详情 `GET /api/runs/{run_id}`。

同输入与规则版本生成相同批号，只保留一条批次。复核入口 `POST /api/runs/{run_id}/review` 提交当前 `revision`，陈旧提交409。归档包只有一个下载入口 `GET /api/export/{run_id}`，含证据、场站对平与运行摘要。原始隔离在页面同屏显示。

SQLite使用命名卷，容器重启后保留历史。要重建演示可在Compose中改用新的卷名称，保留旧卷。

源码在 `app/`，样例在 `sample_data/`，测试在 `tests/`；定义见 `docs/DATA-DICTIONARY.md`，模块和边界测试对应关系见 `docs/DEPTH.md`。输入上限2MB，属于离线复核工具。

采信页支持上传或粘贴CSV。完整源字节与参数随批次持久化，跨页通过run_id读取同一结果。`POST /api/runs/{run_id}/rerun` 读取该批不可变输入快照重新计算，规则未变时批号不变。切换另一示例则创建或复用另一批次。
